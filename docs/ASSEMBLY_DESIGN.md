# 下一阶段：真实片段库驱动的拓扑装配

状态：用户已选择实现方向；本文件记录约定及拟实施规则，不表示代码已实现。

## 已确认的方向

1. 通用框架优先，暂不声称复现 GA-MMPolymer 的原始装配方法。
2. 允许 BRICS 端口成为新的重复单元链端，但需有明确且自洽的规则。
3. 支持多端片段和侧基装配，不只支持线性双端片段序列。
4. 初代从片段库随机组装，不以原始聚合物直接充当种子。
5. 先建立装配、演化、验证和评估契约，以 Mock 测试；真实预测器稍后接入，不在本阶段训练模型。
6. 用户提出把代码复制到线上；目标服务器/目录及数据是否随行尚待确认，不能默认解释为 GitHub 推送或数据上传授权。

## 当前数据盘点

## 拟采用的端口规则

目标：同时允许保留原始链端和产生新链端，避免把未完成组装伪装成合法重复单元。

1. 原始端口（同位素为 0 的 `*`）和 BRICS 端口（同位素标签 > 0）具有不同身份。
2. 原始端口只作链端保留，不参与 BRICS 连接，不自动封氢。一个候选选入的原始端口总数记为 `a`，要求 `0 <= a <= 2`。
3. 连接仅发生于兼容的 BRICS 端口之间，按 BRICS 类型决定键型并消耗两个端口。
4. 完成候选必须是一个连通结构，剩余 BRICS 端口恰好为 `2-a`；这些端口必须满足链端规则（单个邻居、单键、非相邻哑原子）。将它们显式标记为新链端，再转换成无标签 `*`。
5. 其他未连接 BRICS 端口不得残留。不得通过自动删去侧基、自动封氢或把所有哑原子去标签来掩盖失败。
6. 两个原始端口已存在时，所有 BRICS 端口都必须消耗完；没有原始端口时，最终两个链端都可来自 BRICS。
7. BRICS 双键断口不能直接充当要求为单键的聚合物链端；必须正确连接，否则拒绝候选。
8. 完成后统一执行 sanitize、连接性、端点数与结构约束检查，再进入 oracle；拓扑生成/修复重试均有上限。
9. 化学图合法不等于可聚合或可合成；后两者不作为本阶段已证明的性质。

这是实现建议的精确化：不要求两个链端都继承原始数据，但也不任意消除选入片段已有的原始链端。

## 拓扑编码与装配范围

多端片段无法由单纯的片段 SMILES 列表可靠表示连接关系。新的 genotype 至少需要保存：

- 片段实例（同一种片段可重复使用）；
- 边：哪个实例的哪个稳定端口连接到另一个实例的哪个端口；
- 链端选择和来源，以便审计新链端是否来自 BRICS。

同一 genotype 的 decode 必须确定，不在 decode 中随机挑选连接口；随机性只发生在使用 ctx.rng 的生成/算子阶段。端口编号必须与库中固定的规范化片段表示一致。

实现应保留现有 `fragment_seq` demo 行为，通过独立的 `fragment_graph` 编码接入拓扑装配，避免同一编码名在旧配置中悄悄改变端点语义。

首轮实现多端片段、单端侧基片段与树状片段连接；保留片段内部已有的环。新增跨片段闭环反应不是本轮承诺的能力，需要另行实现，而不是把多端片段等同于跨片段成环。

初始化和算子均需维护端口身份与连接记录。交叉可以交换兼容子图，变异可以替换/增删兼容片段或子图；不合法产物在结构过滤阶段拒绝，不消耗预测预算。

## 所需实现

1. Parquet 读取、schema/版本/端口信息验证及配置路径解析；统一两份 CSV 的结构列并规范化去重建库。
2. `fragment_graph` genotype、确定性 decode 和端点选择记录。
3. BRICS 兼容端口索引、随机组装、多端口补全及有界失败处理。
4. 拓扑编码的交叉、变异与连接点守恒；保持旧 fragment_seq 的回归测试。
5. 支持新 genotype 的输出序列化，记录可还原连接关系，不能仅落 repr；这仍不等于实现整个 run 的 resume。
6. 用真实结构库 + Mock 跑通 evolution；记录初始化成功率、算子合法率、失败原因及片段覆盖率，不使用 Mock 声称物性改善。
7. 整理预测器契约与接入位置，但真实模型实现、模型部署及模型性能验收留待下一阶段。
