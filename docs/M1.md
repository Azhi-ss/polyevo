## 明确采用的口径

1. **动态归一化不保证跨代 fitness 单调。** PRD §2 要求整池重算，与 §13 不加条件的 best fitness 单调验收冲突。M1 用固定归一化 demo 验证精英单调，用独立测试验证 minmax_pool 下精英随池重评分。
2. **代数。** `max_generations: 20` 表示 20 次繁殖，另有初始化 Gen0，共 21 个快照；后续论文预设必须明确是否需要 Gen0–Gen49，不能直接把 50 当成相同口径。
3. **预算单位。** 一个预测器对一个结构的实际尝试算一次；失败也计入。多属性结构最后只拿到部分预算时保存已算属性、计账，不让该结构参与评分。
4. **缓存身份。** M1 仅 `star_mode: keep`，缓存键为 `(predictor.name, canonical_smiles)`。模型、版本或预处理不同必须使用不同名字。未来 StarMode 扩展需处理“多个原始结构映射为同一转换后结构”的去重。
5. **档案分数。** 每代输出保存当时评分供审计；archive 仅保存绝对属性、谱系等，不保存相对评分。当前 best_k 是本代存活者的精英快照，不承诺历史累计最优。
6. **搜索耗尽。** 重试有界；初始化不足时报错；繁殖不足时由生存策略用父代补位；没有子代则停止并记录原因。
7. **配置形状。** 预测器配置的 `name` 是注册名，`property` 是输出属性名和缓存身份，例如 `{name: Mock, property: mock_a}`；固定归一化使用 `{minmax_fixed: [0, 1]}`。
